# 🏗 Architecture Documentation

## 📖 Context
* **Goal of the Repository**: This repository is part of an application named "easy-rag" designed to facilitate media transcription and knowledge base querying. The application provides business value by automating the transcription of media files and integrating the results into a knowledge base, which can be queried for information retrieval. This enhances the efficiency of handling media data and extracting valuable insights.
* **Notable Code Libraries and Services**:
  - **AWS Services**: Utilizes AWS Lambda for serverless computing, AWS S3 for storage, AWS Transcribe for transcription services, AWS API Gateway for API management, AWS CloudWatch for logging, AWS IAM for access management, AWS Secrets Manager for secure storage of API keys, and AWS SQS for message queuing.
  - **Pinecone**: Used for vector storage and retrieval, facilitating the knowledge base's vector search capabilities.
  - **Rust Libraries**: Includes `aws-sdk-s3`, `aws-sdk-transcribe`, `aws-sdk-bedrockagent`, `lambda_http`, `serde_json`, and `serde_valid` for various functionalities like HTTP handling, JSON processing, and data validation.

## 📖 Overview
* **Architecture Overview**: The architecture is serverless, leveraging AWS Lambda functions to handle different tasks such as creating media upload links, starting transcription jobs, handling successful transcriptions, and querying the knowledge base. The system uses AWS S3 for storing media files and metadata, and AWS Transcribe for converting media files into text. The transcription results are stored in a knowledge base powered by Pinecone, which can be queried via an API Gateway.
* **Component Interactions**:
  - **API Gateway**: Routes HTTP requests to the appropriate Lambda functions.
  - **Lambda Functions**: Perform specific tasks such as creating presigned URLs for media uploads, starting transcription jobs upon media upload, processing transcription results, and querying the knowledge base.
  - **S3 Buckets**: Store media files, transcription results, and metadata.
  - **Event-Driven Flows**: S3 bucket notifications trigger Lambda functions to start transcription jobs.
  - **Design Patterns**: The architecture follows a serverless pattern, utilizing event-driven and microservices principles.

## 🔹 Components

| Component                              | Description                                                                                   |
|----------------------------------------|-----------------------------------------------------------------------------------------------|
| `create_media_upload_link_lambda`      | Generates presigned URLs for uploading media files to S3.                                     |
| `start_transcription_job_lambda`       | Initiates transcription jobs when new media files are uploaded to S3.                         |
| `handle_successful_transcription_lambda` | Processes transcription results, stores them in the knowledge base, and triggers ingestion.   |
| `query_knowledge_base_lambda`          | Handles queries to the knowledge base, retrieving and generating responses based on stored data. |
| `AWS S3 Buckets`                       | Stores media files, transcription results, and metadata.                                      |
| `AWS Transcribe`                       | Provides transcription services for media files.                                              |
| `Pinecone`                             | Manages vector storage and retrieval for the knowledge base.                                  |

## 🔄 Data Flow

| Data Flow Step                          | Description                                                                                   |
|-----------------------------------------|-----------------------------------------------------------------------------------------------|
| Media Upload                            | Users upload media files via presigned URLs generated by `create_media_upload_link_lambda`.    |
| Transcription Job Start                 | `start_transcription_job_lambda` is triggered by S3 events to start transcription jobs.       |
| Transcription Processing                | `handle_successful_transcription_lambda` processes completed transcriptions and updates the knowledge base. |
| Knowledge Base Query                    | `query_knowledge_base_lambda` handles queries, retrieving data from the knowledge base and returning results. |

## 📝 **Codebase Evaluation**

**Objective**: Analyze the provided codebase for technical debt, focusing on dependency & coupling, code complexity, and cloud anti-patterns.

- **Dependency & Coupling**: The codebase effectively uses AWS SDKs and Rust libraries, maintaining a modular structure with clear separation of concerns across different Lambda functions. However, there is a potential for tight coupling between Lambda functions and specific AWS services, which could be mitigated by abstracting service interactions into separate modules or interfaces.
  
- **Code Complexity**: The code is generally well-structured, but some functions, such as `handle_transcription_job`, could benefit from further decomposition to reduce complexity and improve readability.

- **Cloud Anti-Patterns**: The use of environment variables for configuration is appropriate, but care should be taken to ensure that sensitive information is not exposed. The use of hardcoded values, such as region specifications, should be minimized to enhance flexibility and scalability.

**Actionable Suggestions**:
- Refactor complex functions into smaller, more manageable units.
- Abstract AWS service interactions to reduce coupling and improve testability.
- Review and enhance error handling to ensure robustness.
- Consider using configuration management tools to handle environment-specific settings dynamically.
