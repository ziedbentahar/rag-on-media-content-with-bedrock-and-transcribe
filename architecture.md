# 🏗 Architecture Documentation

## 📖 Context
* **Goal of the Repository**: The repository is part of an application named "easy-rag" designed to facilitate media transcription and knowledge base querying. It provides business value by automating the transcription of media files and enabling efficient querying of a knowledge base using AWS services.
* **Notable Services and Libraries**:
  - **AWS Services**: AWS Lambda, AWS S3, AWS Transcribe, AWS API Gateway, AWS CloudWatch, AWS IAM, AWS Secrets Manager, AWS SQS, AWS Bedrock.
  - **Third-party Services**: Pinecone for vector storage.
  - **Libraries**: `aws-sdk-s3`, `aws-sdk-transcribe`, `aws-sdk-bedrockagent`, `serde`, `serde_json`, `serde_valid`, `nanoid`, `reqwest`.

## 📖 Overview
* **Architecture Overview**: The architecture is serverless, leveraging AWS Lambda functions to handle various tasks such as media upload, transcription job initiation, handling successful transcriptions, and querying the knowledge base. The system uses AWS S3 for storage, AWS Transcribe for transcription services, and Pinecone for vector storage.
* **Component Interactions**:
  - **API Gateway**: Routes HTTP requests to appropriate Lambda functions.
  - **Lambda Functions**: Perform tasks such as creating media upload links, starting transcription jobs, handling transcription results, and querying the knowledge base.
  - **S3 Buckets**: Store media files, transcription results, and metadata.
  - **Event-Driven Flows**: S3 events trigger Lambda functions to start transcription jobs.
  - **Design Patterns**: Event-driven architecture, serverless computing.

## 🔄 Data Flow
| Data Flow Step                         | Description                                                                                   |
|----------------------------------------|-----------------------------------------------------------------------------------------------|
| Media Upload                           | Users upload media files via a presigned URL generated by the `create_media_upload_link` Lambda function. |
| Transcription Job Initiation           | S3 event triggers the `start_transcription_job` Lambda function to initiate transcription.    |
| Transcription Handling                 | `handle_successful_transcription` Lambda processes transcription results and updates the knowledge base. |
| Knowledge Base Query                   | `query_knowledge_base` Lambda handles queries against the knowledge base using Bedrock and Pinecone. |

## 📝 **Codebase Evaluation**
* **Dependency & Coupling**: The codebase uses AWS SDKs and third-party libraries like `serde` and `reqwest`. The use of environment variables for configuration promotes loose coupling.
* **Code Complexity**: The code is modular, with separate functions for each task. However, error handling could be improved for robustness.
* **Cloud Anti-patterns**: 
  - **Hardcoded Secrets**: Secrets are managed using AWS Secrets Manager, which is a best practice.
  - **Inefficient Scaling**: The use of AWS Lambda ensures automatic scaling based on demand.
  - **Improper Error Handling**: Error handling in some functions could be more comprehensive to ensure all potential errors are caught and managed.

**Suggestions**:
- Improve error handling by ensuring all potential errors are caught and logged.
- Consider using structured logging for better traceability and debugging.
- Review IAM policies to ensure the principle of least privilege is followed.
