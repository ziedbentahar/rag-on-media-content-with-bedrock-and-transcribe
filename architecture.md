# 🏗 Architecture Documentation

## 📖 Context
* **Goal of the Repository**: The repository is part of an application named "easy-rag" designed to facilitate media transcription and knowledge base querying. It provides business value by automating the transcription of media files and integrating the results into a knowledge base, which can be queried for information retrieval. This enhances the efficiency of handling media content and extracting valuable insights.
* **Used Services and Libraries**:
  - **AWS Services**: AWS Lambda, AWS S3, AWS API Gateway, AWS CloudWatch, AWS IAM, AWS Transcribe, AWS Secrets Manager, AWS SQS, AWS Bedrock.
  - **Third-party Services**: Pinecone for vector storage.
  - **Libraries**: `aws-sdk-s3`, `aws-sdk-transcribe`, `aws-sdk-bedrockagent`, `serde`, `serde_json`, `serde_valid`, `lambda_http`, `nanoid`.

## 📖 Overview
* **Architecture Overview**: The architecture is serverless, leveraging AWS Lambda functions to handle various tasks such as media upload, transcription job initiation, handling successful transcriptions, and querying the knowledge base. The system uses AWS S3 for storage, AWS Transcribe for transcription services, and Pinecone for vector storage. API Gateway is used to expose HTTP endpoints for media upload and knowledge base queries.
* **Component Interactions**:
  - **API Gateway**: Routes requests to appropriate Lambda functions.
  - **Lambda Functions**: Perform tasks such as creating media upload links, starting transcription jobs, handling transcription results, and querying the knowledge base.
  - **S3 Buckets**: Store media files, transcription results, and metadata.
  - **Pinecone**: Stores vectorized transcription data for efficient querying.
  - **Event-driven Flows**: S3 events trigger transcription jobs, and CloudWatch events handle transcription success or failure.
* **Design Patterns and Architectural Decisions**:
  - **Serverless Architecture**: Utilizes AWS Lambda for scalable, event-driven processing.
  - **Event-Driven Architecture**: S3 and CloudWatch events trigger Lambda functions.
  - **Microservices**: Each Lambda function serves a specific purpose, promoting modularity.

## 🔹 Components

| Component                              | Description                                                                                     |
|----------------------------------------|-------------------------------------------------------------------------------------------------|
| `media-rag` Module                     | Terraform module managing the infrastructure for media processing and knowledge base querying.  |
| `create_media_upload_link` Lambda      | Generates presigned URLs for media uploads to S3.                                               |
| `start_transcription_job` Lambda       | Initiates transcription jobs when new media is uploaded to S3.                                  |
| `handle_successful_transcription` Lambda | Processes successful transcription results and updates the knowledge base.                      |
| `query_knowledge_base` Lambda          | Handles queries to the knowledge base, retrieving and generating responses.                     |
| AWS S3 Buckets                         | Store media files, transcription results, and metadata.                                         |
| AWS API Gateway                        | Exposes HTTP endpoints for media upload and knowledge base queries.                             |
| Pinecone                               | Provides vector storage for transcription data.                                                 |

## 🔄 Data Flow

| Data Flow Step                         | Description                                                                                     |
|----------------------------------------|-------------------------------------------------------------------------------------------------|
| Media Upload                           | Client uploads media via a presigned URL generated by `create_media_upload_link` Lambda.        |
| Transcription Initiation               | S3 event triggers `start_transcription_job` Lambda to start a transcription job.                |
| Transcription Processing               | AWS Transcribe processes the media file and stores the result in S3.                            |
| Transcription Handling                 | `handle_successful_transcription` Lambda processes the result, updates metadata, and ingests data into Pinecone. |
| Knowledge Base Query                   | `query_knowledge_base` Lambda retrieves and generates responses based on the knowledge base data. |

## 📝 **Codebase Evaluation**

**Objective**: Analyze the provided codebase for technical debt, focusing on dependency & coupling, code complexity, and cloud anti-patterns.

- **Dependency & Coupling**: The codebase is modular, with each Lambda function handling a specific task. This reduces coupling and enhances maintainability. However, ensure that shared modules are well-documented to avoid hidden dependencies.
- **Code Complexity**: The use of Rust and its libraries like `serde` and `aws-sdk` promotes efficient and type-safe code. Ensure that error handling is consistent across all functions to maintain robustness.
- **Cloud Anti-patterns**: 
  - **Hardcoded Secrets**: Secrets are managed using AWS Secrets Manager, which is a best practice.
  - **Inefficient Scaling**: The serverless architecture inherently supports scaling, but monitor Lambda execution times and memory usage to optimize performance.
  - **Improper Error Handling**: Ensure all potential errors are logged and handled gracefully, especially in network calls and AWS service interactions.

**Suggestions**:
- Refactor any tightly coupled modules to enhance modularity.
- Regularly review and update IAM policies to follow the principle of least privilege.
- Implement comprehensive logging and monitoring to quickly identify and resolve issues.
